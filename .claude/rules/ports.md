# 포트 할당 규칙

> **단일 출처(SSOT)는 `docs/PORTS.md` 의 전체 포트 표다.** 이 문서는 규칙만 담는다.

@docs/PORTS.md

## 핵심 규칙

1. **새 서비스/Agent 포트는 `docs/PORTS.md` 표에서 빈 번호를 확인하고 잡는다.**
2. 충돌 회피 대역:
   - `8080` → Airflow
   - `9000`, `9001` → MinIO
   - `5000` → MLflow (macOS Control Center 충돌 시 5001)
   - `3000` → Grafana, `9090` → Prometheus, `5432` → Postgres
3. Agent 는 **8000번대** 사용 (현재 8001~8005). 컨테이너 내부 포트는 관례상 `8000`, 호스트 포트만 신규 할당.
4. 포트를 추가/변경하면 **반드시 같은 PR 에서 `docs/PORTS.md` 표를 갱신**한다. (리뷰 체크 항목)
5. 상태 표기: `예약`(번호만 선점) / `활성`(동작 중) / `폐기`(제거 예정).
6. 외부 노출 표기: `O`(호스트 접근) / `△`(dev 전용) / `X`(컨테이너 내부 전용). 운영에서 불필요한 외부 노출 금지.

## 공용 서버에서 동시 작업 (영구 포트 vs dev 포트)

여러 팀이 한 서버에서 동시에 개발/테스트하므로 포트를 두 종류로 나눈다.

- **영구(운영) 포트**: PORTS.md 표에 박히는 번호. push 되면 이 번호로 합쳐진다. (예: 새 agent 8006)
- **dev 테스트 포트**: 운영을 안 건드리도록 팀 오프셋(`기준 + 팀×100`)으로 띄운다. 각자 `.env` 에만 두고 **commit 하지 않는다.** (팀별 오프셋 표는 `docs/PORTS.md` "팀별 dev 포트")

준수 사항:
- 테스트로 `make up`(`-p dais`) 과 운영 :8005 를 건드리지 않는다.
- dev 포트·`localhost:81xx` 주소를 코드/compose 에 하드코딩하지 않는다 → 환경변수로 (`@.claude/rules/security.md`).

새 Agent 추가 전체 절차: `@.claude/rules/new-agent.md`
